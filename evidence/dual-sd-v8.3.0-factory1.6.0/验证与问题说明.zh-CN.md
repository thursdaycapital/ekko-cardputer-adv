# SD 录音更新：验证与问题记录

## 改动及证据

仅更新原厂 app（factory-ekko-v1.6.0-zh），继续保留 Aa、Fusion Pixel 12px、中文菜单和双固件入口。EkkoStudio app、后台和网络绑定不在本次修改范围。

- AppRecord 从 1 秒 RAM 环形回放改成 SD WAV 流式录制/保存/列表/回放，PCM 三块共 24KiB。录音中先补入空闲采集块再写已完成块；SDK 持有的块不重用。
- WAV 文件独占创建，不覆盖既有文件；每约 1 秒更新头部并同步，正常停止会排空已提交的录音块、完成文件。G0 停止保存后返回。
- 录音及回放使用非阻塞入队检查、单一虚拟播放声道、阶段超时、清晰错误页和重试。错误/关闭时先结束读写任务再释放 PCM，恢复麦克风配置、音量和键音。

| 发现 | 严重性 / 置信度 | 处理或限制 |
|---|---|---|
| 原程序未把音频写卡，只保存最近约 1 秒在 RAM | P2 / 高 | 改为完整 WAV 文件并提供列表；过去已退出的 RAM 音频不能因此恢复 |
| Mic 原 isRecording 在任务开始前可能返回 0，即使描述符已发布 | P1 / 高 | 独立队列计数与 canRecord；release/acquire 发布和回收 PCM |
| SDK 首次启动未记忆采样率，第二次入队可能重新启动 | P2 / 高 | 成功初始化时记录实际采样率；测试保留两块排队请求，不无故重启；旧调度风险未声称已在硬件抓到 |
| SDK I2S 失败、零字节或不足样本对时可能沿用旧 scratch PCM | P2 / 高 | 等待重试并检查取消，不生成旧数据；App 3 秒无进展提示错误 |
| SDK 奇数样本长度可能越界写 1 个样本 | P2 / 高 | 按剩余长度截断；实际方法测试覆盖 8/16bit、mono/stereo 目的及奇数长度；App 固定偶数块 |
| 仅看双队列总数不能保证 flip 目标槽已空，调用仍可能短暂等待 | P2 / 高 | 新 canRecord/canPlay 查询目标槽后入队；只支持应用任务单 producer，不能并发 config/end/stop |
| 卡移除后的卸载调用可能已释放 card 指针后才报清理失败 | P1 / 高 | 卸载前先清 HAL 指针和 mounted 状态，避免重试访问已释放指针 |
| 同步 SD 写入/每秒 fsync 可能超过队列采集余量 | P2 / 中 | 在写前补第三块，固定缓冲并记录 max_sd_write_ms；很慢或故障卡仍可能造成断档，尚需实卡验证 |
| 原厂提示音把局部 vector 交异步播放后立即析构 | P1 / 高 | 两个受控声道持有 PCM 至播放结束；旧源码的宿主负面对照触发 ASan heap-use-after-free；该证据不是此次设备崩溃日志 |
| 原厂提示音生成重复左右声道但历史上按 44100Hz mono 播放，音调/时长与目标值不同 | P3 / 高 | 本次明确保留原有 PCM 与实际听感；未顺带改变音色 |
| 修复后的提示音池有 32KiB 总 PCM 上限，密集按键或过长旋律会跳过新音 | P3 / 高 | 有界、无长等待；现有调用均为短提示，play_melody 当前无外部调用；不是用于长音乐的播放器 |
| 录音增益 128 可能削顶 | P2 / 中 | 保留原厂增益，记录峰值；实际麦克风电平与听感待验，不把内存或增益当成已证实的根因 |
| 正常 G0 先排空保存；框架强制关闭/发生错误时会取消未完成队列 | P3 / 高 | 此时尚未 append 的最多约 512ms 队列尾部可能丢弃，保留已写完整样本；不对突然断电/拔卡承诺完整保存 |
| 列表只显示最新 64 条，序号最大 99999；枚举会扫描目录 | P3 / 高 | 旧文件不删除，电脑可读；极大目录的等待时间未实卡量测 |
| 麦克风启动失败可能留下空 WAV | P3 / 高 | 已调整为麦克风启动成功后才创建文件；磁盘在建头阶段失败仍可能留下空/不完整文件，不主动删除用户文件 |
| 播放进度若按提交量显示会领先声音 | P3 / 高 | 已改为按完成的 PCM 块更新；不声称逐样本精确计时 |
| 原先“OK 回放卡住或重启”的连续日志未捕获 panic | P2 / 中 | 源码修复覆盖明确缺陷，但不能宣称捕获了唯一硬件根因；实体回放和重开仍单独验收 |
| SDK end、文件系统调用仍包含同步驱动操作 | P2 / 高 | 队列等待由应用轮询、SDK 取消已修；不承诺所有损坏卡或驱动故障都绝不阻塞 |

## 已执行检查

- ESP-IDF 5.4.2 / ESP32-S3 / 8MiB 目标构建，检查 app 分区容量。
- 实际 `app_record.cpp` + 真 POSIX WAV 文件系统：15 组 ASan/UBSan；包括超 1 秒录音、全样本时序、跨实例恢复、G0 保存、双队列门控、错误/超时、截断、短写、恢复设置和释放次序。
- 实际 `record_storage.h`：16 组 ASan/UBSan；包括独占命名、已有文件保护、RIFF 边界、8.3 名称、掉写/奇数字节恢复、列表内存上限。Python wave 独立校验正常和短写恢复文件。
- 实际 SDK 17 个完整方法（包含 5 个 inline API）、619 行原文编译：18 组 ASan/UBSan；包括取消、释放旧缓冲后重开、失败回滚、未启动任务的已发布队列、零字节/错误读、奇数长度边界。RTOS、I2S 和寄存器为测试替身。
- 实际 `audio.cpp`：9 组 ASan/UBSan；函数返回后消费 PCM、连续调用、1000 次密集按键、容量上限、失败恢复及取消回收。保留原厂 PCM 逐样本对照。
- 中文字形及实际渲染/行宽检查：零缺字，固定行宽适配 204px 应用画布；字体和 Aa 需求不变。
- 本地 ESP-IDF FAT VFS 源码确认支持 O_EXCL、fsync、ftruncate；仍需真实 SD 卡验证。

macOS 仅启用 ASan/UBSan，不声称完成 LeakSanitizer。宿主测试不模拟 ESP32 调度、ES8311 寄存器、I2S DMA、实体 SD 延迟、电平和扬声器听感。烧录及实机状态以同目录 JSON 为准。

## 实体验收

必须在设备上：录音数秒 → OK 保存 → OK 回放 → G0 退出 → 重进列表回放；再重启设备确认文件仍在。结合串口保存字节数、回放完成、复位原因及用户听感核对，不用编译、模拟或软件画布冒充实机结果。

### 本次用户实测结果

用户明确反馈“两次都能正常回放”：录音 → OK 保存 → OK 回放 → G0 退出 → 重进再回放已通过。记录为用户听感/实体操作验收。此次串口录音观察文件为空，没有有效采样量、写卡耗时或回放完成日志，不伪造这些数据。关机重开后的回放、慢卡极限、电平削顶与异常拔卡仍未作额外实测。
