# 美的空调控制 v1.7.0

本版使用用户已经在 v1.6.2 实测开机、关机正常的方案 B / COOLIX24，默认直接进入正式遥控界面。原厂之外的 EkkoStudio 分区不改；Wi-Fi、账号绑定和其他应用设置不擦除。

## 可操作功能

| 功能 | 固件提供 | 实机确认情况 |
|---|---|---|
| 开机、关机 | 明确的1开/0关；OK应用当前设定并开机 | 沿用先前B开关机实测；本版调温、风速、摆风已由用户确认 |
| 温度 | 17～30℃，1℃步进 | 调温操作已由用户实测通过；17～30℃各温度尚未逐点验收 |
| 模式 | 制冷、制热、除湿、送风、自动 | 编码通过；空调是否有制热等能力取决于实际机型 |
| 风速 | 自动、低、中、高 | 风速调整已由用户实测通过；所有模式与档位组合未逐一验收 |
| 上下摆风、点动 | 独立切换或步进命令 | 上下摆风用户实测通过；点动尚待确认 |
| 睡眠、强力、屏显、清洁 | 独立切换命令，不自动开机 | 待实机逐项确认，机型可能忽略部分命令 |
| 记住设定 | 本机NVS独立ac_remote命名空间保存温度/模式/风速 | 退出重进保存已通过；断电重开未实测，无空调状态回读 |
| 兼容测试、NEC手动 | 更多菜单保留A/B/C候选与原手动地址命令 | A/C整体兼容性未确认 |

## 当前协议不能可靠提供的功能

- 0.5℃：B的温度字段原生为17～30℃整数，不能把整数编码标成半度。
- 定时：固定上游文档注明定时属于另一种COOLIX48帧；当前类没有定时API，不做仅停留此页面才运行的假定时。
- ECO：上游统一接口明确未提供该协议的Econo实现。
- 独立左右摆风：没有相应类setter；上游头文件常量的十六进制注释还有一处误写，不用它冒充已验证功能。
- 温度传感器跟随：设备未接入适合测室温的传感器；不虚构室温或把芯片温度当室温发送。
- 空调真实状态：内置红外链路只有发送，本页显示遥控设定/发送结果，不表示空调回执。使用原遥控器或空调面板会使切换功能的状态无法推断，因此不画未经确认的摆风/睡眠开关真值。

## 发现与处理记录

| 发现 | 严重性 / 置信度 | 处理与边界 |
|---|---|---|
| 旧页只有固定26℃开关，缺少完整参数控制 | P2 / 高 | 新增正式B控制和附加指令菜单 |
| 旧页面默认A，用户实际可用B | P2 / 高 | 正式页默认B，兼容测试另放更多菜单 |
| Fan模式若先setMode再setTemp会覆盖专用温度码，错发为除湿 | P2 / 高（上游源码） | 按官方IRac顺序setTemp→setMode→setFan；与实际函数完整对照 |
| 特殊功能为toggle/step，无状态回读 | P2 / 高 | 仅写切换/点动，不维护未经同步的绝对开关真值 |
| 键盘0或非法矩阵事件可下溢并越界读键值表 | P1 / 高（代码）；现场是否发生未知 | 本轮补输入范围检查与真实源码穷举回归 |
| 键盘clear只清键码，遗留state/isModifier/name/extra等字段 | P2 / 高 | 本轮改为全部重置；主机fake同步真实语义，不把旧字段留作新事件 |
| 键盘IRQ状态读取失败可能被0当作已清除，滞留FIFO事件 | P2 / 高（代码）；现场是否发生未知 | 用可判断错误的读取接口，失败保留重试，详见实际键盘测试 |
| CoolixSwingH常量旁十六进制注释误写成Turbo值 | P3 / 高 | 二进制常量实际不同；不改固定参考字节，不据错误注释添加左右摆风 |
| 空调具体能力尚未逐项实测 | P2 / 高（验证缺口） | 软件编码通过不能当作实体的模式、风速、附加功能全部成功 |
| 切换定时/半度/ECO无法从当前接口可靠实现 | P2 / 高（协议边界） | 明确列出，不伪造完整原遥控器的所有功能 |
| 旧StringIR工具JSON未转义双引号/反斜杠 | P2 / 高（源码）；接收端影响未实测 | 本轮不扩大修改其文字协议，保留既有待修项 |
| RMT非DMA长帧存在SDK中断补充约束 | P2 / 低（关联现场故障） | 无实体波形截断证据，保留先前TX_DONE修复，不盲改载波/DMA |
| Adafruit键盘初始化多次写操作仅最后一次结果决定成功，matrix写失败也未检查 | P2 / 高（源码）；正常初始化是否受影响未知 | 独立既存初始化缺口，本轮原始事件窄修未扩展处理，保留待修 |
| Keyboard重复init覆盖旧指针、失败重试可能泄漏，GPIO安装返回值未检查 | P3 / 高（源码）；正常启动只调用一次 | 保留待修，未声称造成现场错误 |
| NEC回调先于App帧处理，退出当帧可能先发命令 | P2 / 高（事件顺序） | 本轮改为回调只排队，App先处理G0/页面退出再执行手动命令；增加回归 |
| 只改草稿后G0退出，若NVS写失败只有日志反馈 | P3 / 高 | 不阻止退出；发送完成后的保存失败有屏幕提示，此退出路径仍属已知边界 |
| UI测试README旧事件说明落后于fake实现 | P3 / 高 | 本轮已同步文档与真实每帧清事件/读取不消费语义 |
| 无线/原厂既存构建警告 | P3 / 高 | 构建通过不称零警告 |

主机协议测试：59个实际固定上游函数、658套完整波形、5047组非法输入；键盘测试：256个原始输入及65,536个公开坐标；UI：29组ASan/UBSan。上述不代替实体空调或硬件波形测试。

最终构建、烧录、输入与空调功能验收分别记录在状态JSON及测试日志。旧版SD录音、Ekko语音和字体的验收不冒充本版重新进行的实测。

## v1.7.0 实机验收补充

用户完成设备与空调测试，直接回复“调温、风速都正常”“摆风正常，设定也保留”。据此确认：温度调整、风速调整、上下摆风及G0退出后重新进入的设定保留均通过本版实机验收。

此结果来自用户观察，不冒充新捕获的USB发送记录。未逐项确认其他模式、摆风点动、睡眠、强力、屏显、清洁或整机断电重启后的设定保留；前述软件测试及协议限制继续有效。
